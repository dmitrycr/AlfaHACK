# Алгоритм обработки источников

## Состав

Сбор разделён на Fetcher, адаптер формата, нормализацию и транзакционное сохранение.
В рабочем запуске разрешён только FixtureFetcher. Он возвращает зарегистрированные
локальные ответы и никогда не переключается на сетевую загрузку при ошибке.
HTTPFetcher существует для тестов таймаутов, статусов, ограничений и redirects.

Лимит сырого ответа — 2 MiB. Лимиты сообщения Kafka у producer, consumer и брокера
согласованы на 3 MiB с запасом на JSON-метаданные и экранирование текста.

Конфигурация: `services/news-service/internal/source/fixtures/sources.json`.
Схема: `contracts/events/sources.schema.json`. В конфиге задаются ID, формат,
расписание, приоритет, допустимые домены, часовой пояс, форматы даты, полнота ленты,
селекторы, JSON-mapping, пределы страниц/записей и версия.

## Порядок

1. Планировщик выбирает просроченный источник по next_run_at и приоритету.
2. Сервис атомарно получает lease источника; второй процесс его не забирает.
3. Получает lease домена: одновременно не выполняются загрузки одного домена.
4. Создаёт run с correlation_id. Сбор ограничен 45 секундами.
5. Загружает страницу с сохранёнными ETag/Last-Modified.
6. Сохраняет ограниченный raw-ответ для диагностики.
7. Адаптер извлекает кандидатов и следующую страницу.
8. Кандидаты, снимок настроек и состояние HTTP-кеша сохраняются атомарно.
9. Worker получает задание, при необходимости загружает полный текст.
10. Нормализует поля, сохраняет публикацию/ревизию и outbox одной транзакцией.
11. Закрывает задание и освобождает lease. Ошибки сохраняются отдельно.

Снимок задания включает настройки адаптера и мок-ответов. Обновление конфигурации
не меняет интерпретацию уже поставленного задания. Служебный `collect` захватывает
каждый источник явно, чтобы фоновый worker не подменил запрошенный сценарий.

## Форматы

RSS 2.0: guid — строковый идентификатор в пределах источника; link — отдельное
поле. `content:encoded` предпочтительнее description. У источников с анонсами
полный текст загружается по ссылке. Дата канала не подменяет дату элемента.

Atom 1.0: выбирается alternate-ссылка HTML, id сохраняется как идентификатор.
published и updated хранятся раздельно. Отсутствующий published не заменяется updated.

HTML: список разбирается по items/link/next, статья — по title/body/date.
Поддерживаются exclude-селекторы, JSON-LD NewsArticle/@graph, метатеги и ограниченный
fallback на h1/article. JS не исполняется, изображения и скрипты не скачиваются.
Страница без текста получает `article_body_not_found`.

JSON: путь до массива и полей задаётся точечными ключами. Неверный тип массива
отклоняет страницу; неверные поля отдельной записи изолируются на этапе проверки.
Поддерживается строковый next. Произвольные выражения из конфига не выполняются.

XML и HTML поддерживают объявленные кодировки, включая Windows-1251. У HTML можно
явно задать charset. JSON должен быть UTF-8. XML с DOCTYPE и вторым корневым
элементом отклоняется; внешние сущности не загружаются.

## Проверки и идентичность

У публикации источника обязательны URL, дата, заголовок и текст. Неизвестная дата
не заменяется временем сбора. Будущая дата сохраняется с quality flag; короткий
текст также получает флаг. Числа, проценты и отрицания при очистке сохраняются.

URL нормализуется без удаления смысловых query-параметров. Удаляются fragment и
известные рекламные параметры. Canonical используется только в разрешённом домене.
Исходная ссылка сохраняется отдельно от нормализованной.

Точное повторение определяется по источнику, области доступа, external_id/URL и
хешу нормализованного содержания. Разные СМИ не теряют собственные записи.
Замена дат/чисел масками для поиска дублей не используется.

Ручной текст — отдельное происхождение manual: URL может отсутствовать, дата
публикации может быть неизвестна, submitted_at не выдаётся за published_at.
Idempotency-Key связан с компанией, пользователем и хешем запроса; другой текст
с тем же ключом даёт конфликт.

## Восстановление

У заданий состояния pending/running/retry/stored/quarantined/failed. Задание с
истёкшим lease снова доступно. Устаревший worker не может завершить чужой lease.
Ожидание занятого домена не считается ошибкой источника или попыткой HTTP.

ETag ленты и задания статей независимы. Для 304 используется сохранённое тело
ленты: повторно проверяются кандидаты и пагинация, но версии не дублируются.
Через час выполняется безусловная перепроверка. Циклы next и превышение лимитов
дают явную ошибку; состояние не выдаётся за полный успешный сбор.

429 и временные серверные/транспортные ошибки дают ограниченные повторы задания,
не более трёх попыток всего. Retry-After учитывается. Outbox при недоступности
брокера сохраняется и повторяется с увеличивающейся паузой, без удаления сообщения.

Raw хранится семь дней. Исходные версии публикаций сохраняются дольше для
трассируемости. Кеш ленты не является единственным местом хранения задания.

## Подключение реального источника позже

Сначала сохраняются тестовые ответы и выбирается поддерживаемый адаптер. Затем
настраиваются поля, домены, даты, пагинация и полнота текста; добавляются тесты
дублей и обновлений. Только после проверки включается отдельно согласованный
режим HTTP. Добавления строки в конфиг достаточно для поддерживаемого формата;
новый формат или JS-страница потребуют нового адаптера.
