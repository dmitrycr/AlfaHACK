В Compose зафиксирован PostgreSQL 17.6; его контейнерный запуск отдельно не проверен.

Сквозной результат: семь публичных публикаций, шесть групп точных дублей и шесть
кандидатов событий. Повторный сбор не создаёт новые версии. Изменение статьи
создаёт одну новую ревизию и обновляет ссылку в событии. Ручная загрузка без даты
и URL сохраняет неизвестные значения; другая компания не может получить её,
задание или приватное событие. Выход отзывает сессию.

Тесты восстановления проверяют потерю ответа брокера, повтор сообщений,
транзакционный rollback, ошибку одной Kafka-партиции при наличии других,
истечение lease, устаревшего worker, прерванный запуск источника и запоздалые теги.
Отдельно проверена доставка сообщения размером больше 1 MiB.

Kafka-проверка локально использует официальный mock пакета franz-go; это не
результат проверки отказоустойчивости настоящего Apache Kafka. Для полного
контейнерного сценария настроен отдельный E2E job в CI. Сам CI удалённо в рамках
этой работы не запускался.

Реальные новостные источники и LLM не вызывались. Файлы frontend/ и ml/ не изменены.
Тестовые процессы и временный PostgreSQL после проверки остановлены.

## Регистрация сотрудников

В тот же день повторены make check, make race, проверка контрактов и native-e2e
с E2E_VALIDATE_CONTRACTS=true после добавления регистрации. Все проверки прошли.
Конфигурация Compose прошла config --quiet; полный контейнерный сценарий повторно
не запускался. Native E2E по-прежнему использует PostgreSQL и Kafka-мок kfake.

Дополнительно проверены:

- ИНН с неверной контрольной цифрой, неизвестная компания, несовпадение названия,
  нормализация кавычек/регистра/пробелов и явно заданные алиасы.
- Запрет внутренних проверок реквизитов без подписи регистрации Gateway.
- Обязательные поля сотрудника, отклонение поля региона, байтовый лимит пароля.
- Повторы и конкурирующие регистрации без дублирования пользователей и компаний.
- Конфликт Idempotency-Key и восстановление повторного ответа при недоступном реестре.
- Отсутствие аккаунта при сбое проверки компании.
- Перевыпуск токена почты, истечение срока и запрет повторного использования.
- Запрет бизнес-доступа до подтверждения почты и отдельного одобрения привязки.
- Получение мок-письма, одобрение и отзыв через настоящие операторские команды.
- Отзыв действующих сессий и запрет нового входа после блокировки.
- Сохранение импортированного обогащения и ИНН при повторном обращении.
- Обновление схемы с 001 до 002 с сохранением прежнего пользователя и сессии.
- Соответствие реальных ответов новых HTTP-методов OpenAPI.

Сквозной отчёт содержит registration_and_membership=passed. Новый профиль компании
содержит okved=null до обогащения, пустые регион/отрасль и не содержит выручку.
Регистрация не создаёт аналитический профиль без данных. Настоящие реестры,
доставка писем, фронтенд и ML не подключались.


## LLM-контур на моках, 23 октября 2026

Пройдены `make check` с PostgreSQL-интеграционными тестами, `go test -race` для
новых очередей/LLM, AI/Insight и Event Service, JSON Schema/OpenAPI с 11 новыми
примерами и проверка Compose `config --quiet`. Новые сервисы собираются отдельно
с `GOWORK=off`, как при Docker-сборке. Полный Docker-сценарий не запускался.

Native E2E с `E2E_VALIDATE_CONTRACTS=true` запускает семь реальных Go-процессов
под отдельными ролями: семь статей → шесть готовых событий → проверенная карточка
→ диалог и ответ со ссылками. Проверены повторы POST без дублирования, конфликт
ключа, запрет чтения карточки/журнала/диалога/сообщения другой компанией. Прежние
проверки регистрации, ручной приватной загрузки и обновления статьи также прошли.

Отдельные тесты проверяют доступ другого пользователя той же компании к чату,
порядок сообщений, кеш по содержимому и области доступа, учёт резерва бюджета,
некорректный оплаченный ответ без кеширования, истечение lease и поздний worker,
rollback callback, три попытки, устаревшие карточки, сбой тегирования и отсутствие
источника. Внешний Match проверен через мок-клиенты зависимостей и реальную БД.

Реальная модель, реальный ML и knowledge-service не подключались. Мок-поиск
и мок-скоринг отделены от адаптеров будущих интеграций. Frontend и ML не менялись.


## Оркестратор агентов и HTTP-адаптер v2, 23 октября 2026

Пройдены `make check` с PostgreSQL, race-тесты общих LLM/очередей/pipeline и
AI/Insight/Event Service, сборка AI и Insight с `GOWORK=off`, проверка OpenAPI
и 13 JSON-примеров, Compose config для базы и HTTP egress overlay. Native E2E
запускает семь сервисов, предварительно ставит профиль в очередь, затем проверяет
три агентных шага карточки (DeepSeek/Qwen/Gemma), переиспользование профиля для
двух событий, журнал workflow, чат, идемпотентность и запрет доступа другой компании.

HTTP тестируется на локальном сервере с фиктивным секретом. Проверены точное тело
запроса и модели, неизвестная тарифная единица/отсутствующие подтверждения без
сетевого обращения, 400/401/403/404/422/429/5xx, редирект, connect-failover до
отправки и запрет повтора после отправки, повреждённые/большие ответы, неизвестный
usage, reasoning без двойного учёта, известный ключ в ответе и JSON unicode-экранирование.
Также проверены остановка при ошибке контракта бюджета и отсутствие повторов 401.

Один финальный ресурсный прогон: 1000 запросов после прогрева, закрыто 1050/1050
тел ответов, goroutine 2 → 2, HeapAlloc после GC 448048 → 555872 байта. Настоящий
локальный transport: 405 запросов, peak активных 4, goroutine 6 → 6, HeapAlloc
675608 → 791904 байта. Это конкретные измерения, а не универсальные гарантии.

Длительный локальный прогон `LLM_SOAK_SECONDS=30`: четыре работника, 21207 попыток
после прогрева, 21302 запросов на локальном сервере с учётом прогрева, отмены и
429. После остановки работников и закрытия пула goroutine 6 → 3; HeapAlloc
610472 → 924960 байт. Промежуточные значения после GC: 1348080, 1406912, 1295864,
1439296, 1521456 байт. Рост удерживаемых ресурсов за границы теста не обнаружен.
Команда воспроизведения — `make llm-soak`; измерения зависят от окружения.

Дополнительные PostgreSQL-тесты проверяют продолжение с checkpoints после
временного сбоя проверки, общий кеш профиля для разных новостей, отсутствие
повторного оплачиваемого вызова после uncertain и сохранение резерва, исходную
миграцию 001/её checksum и сохранение прежних заданий/вызовов при upgrade 002.
Событие с нулевой релевантностью не должно запускать агентов интерпретации.

`check-llm-config`: mode=mock, key_configured=false, payment_gate_open=false,
price_unit_tokens=0. Реальные ключи и LLM API не использовались. Формат /key/info,
параметр ограничения вывода, семантика usage и единица тарифа остаются предметом
подтверждения до платного запуска. Нельзя считать эти локальные тесты проверкой
живого шлюза или доказательством отсутствия всех возможных утечек.

Шлюз получил дополнительную сеть gateway-access; backend осталась internal.
Контейнеры Gateway и AI пересозданы без удаления БД. Подтверждена публикация
127.0.0.1:8080->8080/tcp, healthz=status:ok и readyz=status:ready с хоста.
Все семь прикладных сервисов healthy. `make e2e` через Docker Compose завершился
result=passed: семь публикаций, шесть событий, карточки/чат, кеш профиля,
приватность, обновления, идемпотентность и регистрация/привязка компании.

Диагностика AI: mode=mock, key_configured=true, payment_gate_open=false.
Ключ сохранён только в локальном игнорируемом .env с правами 0600; совпадений
его значения среди Git-visible файлов не найдено. .env исключён из Docker context.
Запросы к реальному LLM-провайдеру не выполнялись; наличие ключа не проверяет
его валидность. Платные вызовы остаются заблокированы.
