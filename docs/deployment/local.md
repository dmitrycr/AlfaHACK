# Локальная эксплуатация

`make setup` генерирует секреты, `make up` выполняет Compose up --build --wait.
Секреты не печатаются. Для проверки конфигурации без вывода значений:

```sh
docker compose --env-file .env -f infrastructure/docker/compose.yaml config --quiet
```

Миграции сериализуются advisory-lock своей схемы. Упорядоченные версии и checksum
сохраняются в schema_migrations; изменение уже применённой миграции останавливает
запуск. Runner поддерживает последовательные миграции. Auth и Company применяют
001 и 002, остальные — 001. Новые изменения должны добавляться отдельными
миграциями. Существующие пользователи и сессии сохраняются при обновлении.

Регистрация использует COMPANY_REGISTRY_MODE=mock и EMAIL_DELIVERY_MODE=mock
(значения по умолчанию для локального запуска). В production мок-регистрация
выключена. Настоящие реестры и доставка писем не подключены. Операторские команды
и тестовые компании описаны в [регистрации](../architecture/registration.md).

`make down` останавливает только контейнеры проекта и сохраняет volumes.
Автоматического удаления данных, сброса паролей или rollback в этой итерации нет.
Файлы deploy/rollback/backup и staging/production остаются прежними заготовками.

Шлюз подключён к внутренней сети backend и отдельной gateway-access для
публикации localhost:8080. Остальные прикладные сервисы используют только backend.
После изменения сетей пересоздайте шлюз:

```sh
docker compose --env-file .env -f infrastructure/docker/compose.yaml up -d --no-deps --wait api-gateway
curl --fail http://localhost:8080/healthz
curl --fail http://localhost:8080/readyz
```

Проверка LLM-конфигурации работающего контейнера без запроса к провайдеру:

```sh
docker compose --env-file .env -f infrastructure/docker/compose.yaml exec -T ai-agent-service /app check-llm-config
make e2e
```

Для локальной проверки ожидаются mode=mock, payment_gate_open=false и успешный
результат E2E. key_configured показывает только наличие ключа, не его валидность.
E2E создаёт синтетические записи, проверяет регистрацию, сбор/обновление новостей,
карточки и чат; запускайте его в локальном демонстрационном окружении.
Скрипт E2E использует DEMO_PASSWORD из окружения терминала либо стандартный
демо-пароль README; при изменённом пароле задайте его перед запуском.

Служебный сбор: `make collect`. Параллельный сбор одного источника и одного домена
ограничен lease. Зависший lease освобождается по сроку. Принудительно удалять его
во время работы процесса нельзя: следующий worker сам восстановит задание.

При недоступности Kafka смотрите outbox_pending и outbox_oldest_seconds. Публикации
сохраняются в PostgreSQL, доставка продолжится после восстановления. При ошибке
источника смотрите news.sources, news.runs и news.jobs **под ролью news-service**.
Не подключайте прикладные сервисы к БД суперпользователем.

Счётчики, raw-ответы и приватные данные не публикуются через произвольные SQL-ручки.
Метрики служебных процессов доступны только во внутренней сети Compose. Ответ
analytics/summary фильтруется по компании сессии.

Локальный Compose не является production-конфигурацией. Для внешнего развёртывания
нужны TLS, отдельные сервисные идентичности/ключи, защита брокера, отказоустойчивое
хранение и отдельная процедура резервного копирования. Реальные новостные источники
в этой сборке технически выключены.
