# Как включить (или добавить) сектор

Код менять не нужно: всё лежит в `ml/config/`. Названия секторов копируются в `Event.sectors`, `Profile.sector` и
`CounterpartyShare.sector` символ в символ, поэтому источник названий один: лист «Сектора» в `players_by_sector.xlsx`.

## Включить уже существующий (выключенный) сектор

1. `config/sectors.yaml`: у сектора поставить `enabled: true`.
2. `config/sector_matrix.csv`: добавить строки связей сектора (`from_sector,to_sector,role,strength,rationale`; `role` — `demand` или
   `supply`, `strength` 0..1). Пока выключенный сектор в строках матрицы не участвует, строки можно подготовить заранее.
3. `config/sector_commodities.csv`: добавить сырьё сектора (`sector,commodity,role,rationale`; `role` — `produces` или `buys`).
4. `config/sectors.yaml`: проверить `aliases` сектора (другие написания названия, которыми отвечает модель) и `keywords`
   (начала слов для mock-режима и сопоставления по тексту). Алиас, подходящий двум секторам, лучше не добавлять: он не сработает.
5. Пересобрать профили и экспорт:
   `DATA_DIR=./data/real python scripts/build_profiles.py --force --out out/profiles_real.json`
   `python scripts/export_profiles.py --src out/profiles_real.json --out-dir <папка>`
6. Прогнать тесты (`pytest`) и тегирование (`scripts/run_tagging.py`): список секторов в промпте и ключ кеша тегов
   (`tags:tagging-v3:<хеш секторов>`) обновятся сами, старые теги другого набора секторов не подмешиваются.

## Что делает флаг enabled

| Часть | enabled: true | enabled: false |
|---|---|---|
| Промпт тегирования, `Event.sectors` | сектор в списке | нет; ответ модели с этим сектором отбрасывается |
| Матрица связей и сырьё | строки используются | строки пропускаются |
| Каналы спрос/предложение в профилях | сектор может быть целью канала | не может |
| Профиль клиента сектора | строится | строится, но `out_of_scope: true` |
| Экспорт для команды | профиль выгружается | профиль не выгружается |

## Добавить совсем новый сектор

1. Добавить строку на лист «Сектора» и компании на лист «Игроки по секторам» (колонка ОКВЭД: `B.06, C.19, H.49.5`).
2. В `scripts/make_sectors_from_players.py` добавить ключевые слова сектора в `KEYWORDS`.
3. `python scripts/make_sectors_from_players.py`: перегенерирует `sectors.yaml` (флаги `enabled` и факторы сохраняются, новый сектор
   включён), `aliases.yaml` и `okved_to_sector.json`; скрипт печатает неоднозначные случаи ОКВЭД и алиасов.
4. Дальше шаги 2–6 из раздела выше.

Несопоставленные названия секторов из ответа модели не пропадают молча: они пишутся в лог и в журнал LLM
(`status = note`, `run_id = tag:<event_id>`). Если сокращение встречается часто, добавьте его в `aliases` сектора.
